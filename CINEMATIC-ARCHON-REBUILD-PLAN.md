## 1. THE CORE FIX — the showcase keyframe model (read this twice)

### What went wrong (do not repeat)
The previous workflow used the skill's "3-phase chain" (wide → **setting** → motion, 2 clips per mechanism),
and the middle `setting` frame was generated by asking Nano Banana Pro to **invent a brand-new space from
scratch**. The `generation-plan` command told the model to design scenes as *"a spatial path … push through an
opening → interior reveal,"* and the loop wrote prompts like *"the camera has glided forward through the
entrance **into the great room**"* — describing a whole new room (new furniture, new walls, new everything)
that did **not** exist in the reference frame.

That is the one thing an image model cannot do: NB Pro can't move a camera through space, so when asked for a
space that isn't on screen yet, it **reinvents** one — and the reinvention never matches, producing hard cuts,
morphing, mismatched rooms, and drifting light. **Every run.** The root cause is *invention*, not the keyframe
count and not the camera style — see the rule in "The discipline" below: an edit must **reveal what's already
there, never conjure what isn't.**

### What to build instead — the 2-frame-per-scene model
The user's directive (and the more robust reading of the skill): **two keyframes per scene — one input, one
output — and Seedance does the in-between. No third NB frame in the middle.** This deletes the botch-prone
frame entirely and is exactly how the skill's *hero* video already works (SKILL.md line 575: *"give it a
crystal-clear start frame AND a crystal-clear end frame, its only job is to smoothly interpolate between two
known states. That's where video models excel. That's where they DON'T hallucinate."*).

**The model:**
```
N scenes  ⇒  N+1 keyframes  +  N Seedance clips

  kf0 ──clip1──► kf1 ──clip2──► kf2 ──clip3──► kf3        (example: 3 scenes)
 (fresh)        (edit of kf0)   (edit of kf1)  (edit of kf2)

  • Scene k's clip:  hf-video --start-image kf(k-1) --end-image kf(k)   (BOTH frames, always)
  • Scene k's END frame IS scene k+1's START frame — the SAME FILE, reused, never regenerated.
  • kf0 is the only fresh NB Pro generation. Every later kf is an NB Pro EDIT of the one before it.
```

### Reconciling the skill's "three keyframes, not two"
SKILL.md §2E says: *"Each mechanical reveal in a multi-scene flythrough needs **three** keyframes, not two."*
**Do not let that line pull you back to a middle frame.** Reconciliation:

- The skill's "three keyframes" is a *recommended refinement* for one narrow purpose — to split a single
  mechanical reveal into a pure **camera-travel** clip and a pure **mechanism** clip, so neither clip does two
  motions at once. The third frame exists only to separate those two motions.
- The skill **also fully endorses the 2-frame model**: it is how the skill's own *hero* video works (line 575)
  and how its seam rule reads (line 540, "the end frame of Scene 1 is the start frame of Scene 2").
- We **deliberately choose the 2-frame model** (user-authorized) because that middle frame is exactly where NB
  Pro botched every run, and because "keep each clip's motion clean" can be honored by *how the director scopes
  a scene* (below) instead of by inserting an NB frame that corrupts the chain.

**So: the skill is source-of-truth for creative quality; on keyframe count only, this plan overrides it.** Read
"three keyframes, not two" as "keep each clip's motion clean," and satisfy that through scene scoping.

### The discipline that makes NB edits safe (THE lesson)
The structure that guarantees continuity is non-negotiable: **each keyframe is an NB Pro edit of the prior
keyframe** (`--image kf(k-1)`), so every frame is literally built on the last — same world, for free. Within
that, the **director/prompter has full creative latitude over the camera and the transition** — how far it
travels, how dramatic, what it lingers on, fast or slow. Pick whatever is most cinematic for the scene. Only
two rules are hard, because they are what actually prevents the slop:

1. **Reveal, don't invent.** Whatever is new in the end frame must already be **visible or clearly implied in
   the start frame** — through the doorway, window, opening, or in the distance. The edit *expands what's
   there*; it must never conjure a space that wasn't on screen (SKILL.md line 599, "seed the next scene"). This
   is the single rule the prior build broke. A dramatic camera move is fine; an *unseeded* one is not.
2. **Preserve the unchanged parts.** Use the skill's everything-else-identical clause (*"keep the materials,
   architecture, sky, and light exactly matching the reference image"*) and, for any mechanism, the
   geometry-not-labels craft (SKILL.md §2E 3b: describe the resulting shape — "the lower half is now an open
   rectangular gap, no glass"; never "open the door"; never the word "dark"; negate the wrong open-mode).

Because each frame is an *edit*, it inherits the reference's time-of-day and palette automatically — so just
don't re-specify a different mood mid-chain (that alone caused the dusk→afternoon→dusk drift). An optional
global `lighting` knob in `plan.json` can pin the mood if desired, but it's a knob, not a mandate.

> **Scene scope is the director's call.** A scene may be a mechanism, a pure camera move, or both — Seedance
> interpolates the two endpoints (its job, and it's good at it). The skill notes that cramming a big traversal
> *and* a mechanism into one clip can make Seedance chimera; **if** that artifact shows up, the remedy is to
> split that scene into two clips — but leave that to the director's judgment per scene rather than hard-coding
> "one change only." Maximal creative latitude now; tighten later only if the user asks.

### Worked example (Stonecrest) — one possible shape, not a template to copy
The camera moves and pacing here are just *one* director's choice; another could be more dramatic. What's
fixed is only the chain structure (edit of prior) and reveal-don't-invent.
- `kf0` (fresh): exterior, monumental walnut pivot door **closed**, framed head-on, warm interior glow through
  the door seams and sidelites, mountains behind.
- `kf1` = edit of kf0, **door opens** — pivot door now open ~80°, revealing the foyer + the great-room glass
  wall + mountains *that were already implied through the seams*. Same exterior, same light.
- `kf2` = edit of kf1, **camera carries through to the glass wall** (which is already visible through the open
  door in kf1): now inside, facing the closed lift-and-slide glass, deck visible beyond. Same world & light.
- `kf3` = edit of kf2, **glass slides open** — same room, panels stacked aside, deck + fire pit revealed.
- Clips: `clip1 = kf0→kf1` (door opens), `clip2 = kf1→kf2` (move to the glass wall — the director decides how
  bold), `clip3 = kf2→kf3` (glass opens).

> If a clip's two endpoints are dissimilar enough that Seedance morphs, the remedy is to add an intermediate
> keyframe and split that one scene into two clips — a per-scene judgment call, not a global rule.

### Files to rebuild for this model (♻️)
- **`.archon/scripts/plan-flatten.ts`** — emit the `N+1 keyframes + N clips` chain: `kf0` (refs `[]`),
  `kf(k)` keyframe (refs `[kf(k-1)]`, i.e. an edit of the prior), `clip(k)` (refs `[kf(k-1), kf(k)]`).
  **No `wide/setting/motion` triplet. No per-mechanism 3-phase.** One keyframe + one clip per scene boundary.
- **`.archon/commands/generation-plan.md`** — design the showcase as a chain of scenes where each `end_state`
  is a **coherent evolution** of its `start_state` (a mechanism, a camera move, or both — director's call)
  whose new content is **seeded/visible in the start_state**. The plan schema's showcase becomes:
  `showcase:{ enabled, lighting?:"optional global mood", scenes:[ { label, start_state, end_state,
  seeds_next:"what's visible that the next scene moves into", camera:"the director's intended move & feel" } ] }`.
  Kill `wide_kf/setting_kf/motion_kf`. The plan critic checks: each `end_state` is reachable from `start_state`
  **without inventing an unseeded space**, and each scene seeds the next. (It does NOT police camera drama.)
- **`.archon/workflows/cinematic-site.yaml`** showcase-loop prompt — for each item: if keyframe, NB-edit the
  single ref to its `end_state` — reveal-don't-invent + everything-else-identical + inherit the reference's
  light; if clip, 5-layer Seedance prompt (the director's camera move) with BOTH `--start-image` and
  `--end-image`. (Keep the `ARTIFACTS_DIR="$ARTIFACTS_DIR"` prefix — see §3.)
- **`.archon/assets/cinematic/templates/keyframe-template.md`** — rewrite around "reveal don't invent, preserve
  the rest, inherit the light" (NOT around a fixed camera style). **`clip-template.md` (5-layer Seedance) stays
  as-is** ✅.
- **Showcase rubrics** (`rubrics/keyframe.md`, `clip.md`) — keyframe critic FAILs an edit that **invents an
  unseeded space**, breaks the preserved world, or resets the time-of-day. It does **not** fail on camera
  ambition or transition style — that's the director's latitude.

### Acceptance for the showcase specifically
Extract the seam frames and prove: (a) `kf(k)` end-of-scene file **is byte-identical** to the next scene's
start input (same file, reused — verify in `showcase/plan.json` refs); (b) each keyframe is the **same world**
as the one before it, and every new element in it was **visible/seeded in the prior frame** (open them
side-by-side — if a space appeared that wasn't on screen before, the edit invented it and it's wrong; a bold
camera move is fine); (c) the stitched video reads as one continuous move with no morph at the seams. **No
crossfade band-aids** — continuity must come from the generation, not ffmpeg `xfade`.

## 3. Operational fixes already made — PRESERVE these (they cost real debugging)

1. **Loop shell can't see `$ARTIFACTS_DIR`.** Named scripts get env from Archon, but the loop *agent's Bash
   tool* does not. `plan-step.ts` now reads `process.env.ARTIFACTS_DIR` and **dies loudly if missing** (no
   `argv[2]` fallback — that silently returned `NONE` and made loops no-op without generating). Every
   `plan-step` call in loop prompts is prefixed `ARTIFACTS_DIR="$ARTIFACTS_DIR" bun …`, and `until_bash`
   uses single-quoted YAML so the inner quotes survive.
2. **Higgsfield URL parse.** `lib/util.ts > parseHiggsfieldUrl` must (a) find the JSON block even amid
   progress lines, (b) take `.result_url` from the last completed job, (c) in the line-scan fallback **never
   return an API/polling endpoint** (`…/agents/…`, `…/jobs`, `…/api/…`) and prefer `*.cloudfront.net` / media
   URLs. A naive "last http line" grabbed `https://fnf.higgsfield.ai/agents/uploads/…/confirm` and failed
   every download. Keep the unit test (3 cases).
3. **Optional end-frame must not block the hero.** `hero-gen` node uses `trigger_rule: one_success` so a
   failed *optional* `hero-end-frame-gen` doesn't skip the hero. `gen-hero-video` uses the end frame only if
   `end-frame.png` exists.
4. **Per-variant resilience.** A transient Higgsfield upload failure on ONE hero variant once hard-failed the
   whole node. `hf-video.ts` runtime/network failures now **throw** (not `die()`/exit); its CLI entry catches
   and exits 1. `gen-hero-video.ts` wraps each variant in try/catch, ships any that succeed, sets
   `hero-final.mp4` from the first success, and only `die`s if ALL variants fail. Apply the same pattern to the
   showcase clip generation in the 2-frame rebuild (one failed clip shouldn't nuke the run).
5. **Module legibility + off-domain sample copy.** In `assets/cinematic/modules/`: raise `brand-logo-marquee`
   `.brand-logo-item` opacity 0.4→~0.78, `.brand-logos-label` & `.logo-name` rgba 0.3/0.35→~0.72,
   `before-after-slider` `.ba-caption` 0.6→~0.78. Neutralize restaurant/filler sample text in
   `parallax-sections`, `liquid-glass`, `magnetic-buttons`, `reveal-text`, `marquee`. `assemble-site.ts` has
   dedicated fillers for `parallax-sections` (heading+body+image) and `liquid-glass` (N cards), and
   `fillGeneric` overrides the first heading AND first paragraph. `site-plan.md` must emit real `text` for every
   text-bearing module. `build-check` already greps for low-opacity-on-text and leftover sample strings — keep
   those asserts.
6. **Stall detection — `.archon/scripts/stall-watch.ts`.** A run paused at an approval gate emits no signal;
   a forgotten gate sits forever (we lost ~7h twice). A paused workflow can't watch itself — detection is
   **external**: this script reads the Archon SQLite DB directly and exits non-zero if any run is idle past a
   per-status threshold (`paused`=forgotten gate, `running`=hang, `pending`=never started), printing the run id,
   the stuck gate, and the exact `approve/reject` command. Run it on a loop while driving (`/loop 10m bun
   .archon/scripts/stall-watch.ts`) or cron. **Improvement for v2:** de-dupe — alert once per `(run,gate)`
   entry, not every cycle, so an intentional pause-for-review doesn't spam.

## 4. Verified facts — do not re-derive (live-tested)

- **Image (Nano Banana Pro):** `higgsfield generate create nano_banana_2 --prompt "P" --aspect_ratio 16:9
  --resolution 2k|4k [--image REF …] --json --wait --wait-timeout 8m --wait-interval 5s`. Result = a
  **top-level JSON array**; asset URL = **`.result_url`** (host `*.cloudfront.net`, NOT `cdn.higgsfield.ai`).
- **Video (Seedance 2.0 Fast):** `higgsfield generate create seedance_2_0 --mode fast --prompt "P"
  --start-image S [--end-image E] --duration N(≥4 int) --aspect_ratio 16:9 --resolution 720p
  --generate_audio false --json --wait --wait-timeout 20m --wait-interval 5s`. **`--mode fast` renders 720p
  even if you ask for 1080p** (same cost) — pin `720p`; `extract-frames.ts` upscales to 1920-wide for the
  scroll canvas. Audio flag is underscore `--generate_audio`; frame flags are hyphen `--start-image/--end-image`.
- **Costs (fast):** NB-Pro 2k ≈ 2 cr, 4k ≈ 4; Seedance 8s ≈ 28 cr, 5s ≈ 17.5, 4s ≈ 14. A 2-frame 3-scene
  showcase = 4 keyframes + 3 clips ≈ **~60–90 cr** (much cheaper than the old 7kf/6clip ≈ 150–300).
- **Dry run:** `HF_DRY_RUN=1` makes `hf-image`/`hf-video` synthesize ffmpeg-lavfi placeholders + a fake
  cloudfront URL, and `preflight` reports all-present + 9999 credits. The **entire DAG runs at zero credits** —
  this is the smoke test. Keep every other [DET] script working unchanged under dry-run.

## 7. Verification protocol — the user wants VISUAL end-to-end proof

**L1 — static:** `archon validate` clean. Typecheck every script (`bun build <script> --target=node`).

**L2 — dry-run smoke test (zero credits):** `HF_DRY_RUN=1 archon workflow run … "<smoke brief, showcase+
before/after ON>"`. Drive every gate. Confirm: all guards skip correctly; both loops actually **generate
placeholders** (showcase done-count climbs to `N` items, before/after to its pairs — the old bug was loops
no-op'ing); `build-check` PASS; a full `index.html` is produced; deploy-local finalizes. This proves the DAG +
loop plumbing before spending a credit.

**L3 — real run with visual verification (the acceptance run):** real `archon workflow run` (no dry-run).
- At **plan-gate**: confirm scenes are single-atomic-change with a locked `lighting` and seeded next-areas.
- During showcase generation: as each keyframe lands, **open consecutive keyframes side-by-side** (a `magick
  montage` contact sheet per scene) and verify each is the prior frame + ONE change, same world, same light. If
  a whole room changed, the model regressed — stop and fix the prompt, don't proceed.
- Verify the **seam reuse**: `showcase/plan.json` clip refs must show `clip(k).start == kf(k-1)` and
  `kf(k)` reused as `clip(k+1).start` (same file path).
- At **showcase-gate**: `open` the stitched `showcase-video.mp4` and watch it — one continuous move, no morph,
  no light jump.
- At **hero-gate** / **site-gate**: open the variants and the assembled `index.html`; scroll it.
- Final: **local finalize** copies `site/` + `scenes/` to a durable path and writes deploy-later commands.

**Run `stall-watch.ts` on a loop the whole time** so no gate is ever silently forgotten.

## 9. Meta-principles (the "why it kept feeling like patchwork" lesson)

1. **The workflow is a 1:1 of the skill.** Its only value-add is *tuning knobs* (model tiers, scene/variant
   counts, durations, thresholds, dry-run) — **never** new creative logic. The failure happened because a
   creative operation (how the next keyframe is produced) was silently redefined into "invent a new room."
2. **For every creative node, transcribe the skill's load-bearing rules verbatim — don't paraphrase them into
   something easier.** The prior build quietly turned the skill's keyframe rules into "generate the next space
   from scratch," which is the one thing the image model can't do. The rule that had to survive intact was
   *reveal-don't-invent / seed-the-next-scene* (SKILL.md line 599) and *geometry-not-labels* (§2E 3b) — carry
   those word-for-word. (Note: we are NOT carrying the skill's 3-keyframe count — that's the one authorized
   structural override, §1. Everything *creative* is transcribed; only that *architectural* choice differs.)
3. **When output looks wrong, re-ground in SKILL.md before patching downstream.** The prior debugging fixed
   stitching, then chaining, then resilience — all downstream of a keyframe-semantics error that a re-read of
   SKILL.md §2E would have caught on day one. Fix the source, not the symptom.
4. **An NB Pro edit reveals; it never invents.** If you can't point to where the new content was already
   visible (seeded) in the reference frame, the edit will hallucinate. This is the operational form of (1)–(3).
